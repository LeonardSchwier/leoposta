# Changelog

All notable changes. No tagged release has been published yet.

## Unreleased

### Added
- Calendar: repeating events from the event editor. A "Repeat" control (Never / Daily / Weekly on chosen weekdays / Monthly on the start's day / Yearly; every N; ends never, after N times or on a date) writes an RFC 5545 RRULE. A new timed series is stored as `DTSTART;TZID=<your zone>` with a VTIMEZONE, so it stays at the same local time across summer time and BYDAY means your weekday; UNTIL is UTC for timed events and a DATE for all-day ones. Editing a series shows its rule; changing it replaces only RRULE (EXDATE, changed occurrences, alarms stay); "Never" turns the series into one event and drops its EXDATEs and changed occurrences. A rule the control cannot express (BYSETPOS, "2nd Tuesday", several BY* values, ...) is shown read-only as "Custom repeat" and kept as it is.

### Removed
- Settings: the "Group messages by thread" checkbox. There is no conversation view, so it did nothing.

### Fixed
- The offline reading cache mixed accounts. It is one IndexedDB store shared by every account and was keyed by folder and UID only, so INBOX uid 5 of one account overwrote uid 5 of another (opening a message offline could show the other account's mail), caching one account's `Sent` list deleted the other's rows, the offline list of a folder showed whichever account's mail was cached last, a removed account's mail stayed on the device, and two overlapping list writes could drop each other's rows. Every entry now belongs to an account and every read, write and clear is scoped to it; removing an account deletes its cache; the list is rewritten in one transaction. Entries written by earlier versions have no owner: they are never shown and are deleted on the next list load (it is a cache, nothing is lost). A PWA that starts offline reads the account the browser remembered; nothing is written while no account is active. The account switch no longer clears a folder of the account switched to.
- `GET /api/idle?account=<address>` answered for the first account when the address was not an account (one removed while the page was open); it now answers "No account configured", like an unknown `x-account` header. `MailAPI.idle()` also started its query string with `&` when the build has no API token.
- An account whose address has a character above U+00FF (Cyrillic, CJK, Polish ł, an internationalised domain) made every API call throw: the active account travels in the `x-account` request header, a header value must be a ByteString, and `new Headers().set()` rejects such a value before anything is sent. The whole app was unusable while that account was active, and with one account it could not even be removed in the UI. The client now sends a printable ASCII address unchanged and anything else as `u8:` + the percent-encoded address (`src/lib/accountHeader.ts`, the only place that names the header; used by the API client, the offline outbox, the PGP calls and the PGP section of Settings); the server decodes only that prefix (`decodeAccountHeader` in `server/lib/state.js`), so a plain value, including one with a `%`, keeps today's meaning. A damaged or unknown value is `400 No account configured`, never the first account. A Latin-1 address such as `jörg@...` is now encoded as well; a client talking to an older server (a separate `VITE_API_URL` deployment) must be updated together with it.
- A message written while offline could be sent from the wrong account. The outbox did not record which account it was written under, and the flush sent every message under the account that was active at that moment, so switching accounts before the network returned (or reopening the app with another account remembered) sent it with the other address as From and filed it in the other Sent folder. Each queued message now carries its account and the flush sends `x-account` for it; a message whose account has been removed is refused by the server and stays in the outbox, reported as failed on every reconnect, instead of leaving from another account (there is no way yet to discard or re-target it in the UI; see ROADMAP.md). Messages queued before this change, and messages queued while the accounts had not loaded, still go out under the active account.
- A filter rule with the `regex` operator could freeze the whole server: a backtracking pattern such as `(a+)+$` takes seconds to minutes on a 31-character subject, the tested text is the incoming mail's subject, sender or body, and the server is a single process. Rule regexes now run with a 25 ms limit per match; a message that spends it is skipped for that rule for 5 minutes, regex conditions share a 250 ms budget per 2 s, patterns are limited to 256 characters and only the first 100 000 characters of the text are searched (a match beyond that is not found).
- `PUT /api/rules` stored any array, so a `null` rule or a numeric value made every later message list answer 500. It now accepts only the shape the Rules tab sends (at most 200 rules and 20 conditions per rule, values up to 500 characters, a regex that compiles) and answers 400 with a readable message otherwise; unknown properties are dropped.
- Delete destroyed mail: the Delete button sent `DELETE /api/message/:id` without `toTrash`, and the server then expunged the message, in every folder, with no way back. It now moves the message to the server's Trash (the mailbox flagged `\Trash`, else one called `Trash`, created if the server has none) and removes it for good only when the selected mailbox is that Trash (compared by the server's full path, so a namespace prefix such as `INBOX.Trash` is handled). A failed move or delete (ImapFlow answers `false` instead of throwing) is now a 500 the UI shows, not a silent success that dropped a message the server still had, and a refusal no longer logs the shared IMAP connection out. `toTrash` is ignored (`?toTrash=false` was the truthy string `"false"`). A message id that is not a positive integer is a 400.
- Archive and other moves (`POST /api/message/:id/move`) used ImapFlow's `messageMove`, which on a server without the MOVE extension copies and then expunges even when the copy failed. Moves now copy, check, and only then remove the original.
- `GET /api/idle` leaked a logged-in IMAP session, its mailbox lock and a heartbeat timer whenever the browser dropped the stream while the server was still connecting (every change of inbox-sync mode or active account restarts the stream); the close handler was only registered after the connect. It is now registered first and aborts the pending connect. A failed connect also logs out its half-open client.
- `GET /api/idle` wrote `Access-Control-Allow-Origin: *`, replacing the origin-specific answer of the CORS middleware; the header is gone.
- A request from a disallowed origin or with malformed JSON got Express's HTML stack-trace page (local file paths). Errors are now JSON: 403 `origin_not_allowed`, 400 `invalid_json`, 404 `not_found`, other 4xx `bad_request`, and a generic 500 `internal_error`; 413 `too_large` is unchanged.
- `npm run test:server` ran a single trivial test on Node 22 (`node --test server`), so CI skipped every server test; it now runs all of them (131 with the 2026-11-11 additions).
- A scheduled message whose SMTP send took longer than the 30 s scheduler tick was sent again on every tick until the first send finished; in-flight messages are now skipped.
- `GET /api/status` listed the configured mailbox addresses without the API token; it now requires the token (`/api/health` stays open).
- `openpgp` is imported by the backend but was a dev dependency, so a production install (`npm ci --omit=dev`) crashed at start; it is now a runtime dependency.
- Message dates came from a non-existent field and always showed the current time; they now use the envelope or internal date.
- CI: the route snapshot test no longer depends on whether `dist/` was built; typecheck and end-to-end tests match the current UI.

### Security
- `POST /api/pgp/unlock` locks for the rest of a 60 s window after 5 wrong passphrases (429 `too_many_attempts` with `Retry-After`); the attempt is counted before the decrypt, so concurrent guesses cannot all slip through.
- Upgraded `nodemailer` to 10.4.0 and `vitest` to 5.1.0 to clear audit findings.

### Added
- Import mail (IMAP/SMTP) and WebDAV (calendar/contacts) accounts from GNOME Online Accounts: a "Import from GNOME Online Accounts" box in Settings, hidden when unavailable. Linux + native (non-container) only. See [docs/design/goa-import.md](docs/design/goa-import.md).

### Fixed
- `updateAccount` (`PUT /api/accounts/:email`, and `POST /api/account` on an existing email) silently blanked any field a partial request body didn't mention — found by the GOA import above, which updates an existing account with DAV-only or mail-only fields. Omitted fields now keep their current value; a field sent explicitly (including `''`/`false`, to clear it) still overrides.

- `npm run typecheck`, `npm run screenshots`, README screenshots (light and dark), `SECURITY.md`, `CONTRIBUTING.md`, issue and pull request templates, monthly Dependabot, pinned workflow actions.
